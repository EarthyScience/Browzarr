Browzarr fetches chunks over HTTP(S) directly from the store's host, exactly like a `zarr.open(...)` from Python would — only in your browser.

## Opening a remote store

1. Open the dataset modal (`database +` icon)
2. Choose the **Remote Zarr** or **Icechunk** tab
3. Pick an entry from the searchable catalog, or paste a URL into the **Store URL** field and click **Fetch**
4. Select a variable and plot

Supported remote backends:

- **Remote Zarr** — Zarr v2/v3 stores served over HTTP(S) (e.g. public S3 or GCS buckets via their `https://` endpoint)
- **Icechunk** — Icechunk repositories served over HTTP(S)

## Authentication and request options

- **Remote Zarr** — expand **fetchOptions** to attach an auth header (**None**, **Bearer**, **Basic**, or **API Key**, sent as `X-Api-Key`) and/or arbitrary custom headers. Auth headers are only sent over `https://`; plain `http://` URLs are rejected when headers are set.
- **Icechunk** — expand **Settings** to choose the reference to open (**Branch**, **Tag**, or **Snapshot**; defaults to branch `main`) and to adjust request options such as custom headers, **Credentials**, **Cache**, **Max retries**, and **Retry delay (ms)**.

## Opening a store from a URL

A store can be opened directly by passing it as a query parameter, e.g. `https://browzarr.io/?initStore=<store-url>` (`?dataset=<store-url>` is also accepted).

## CORS

Because the browser (not a server) performs the requests, the remote host must send permissive **CORS** headers:

```
Access-Control-Allow-Origin: *
# or restrict to the Browzarr origin
Access-Control-Allow-Origin: https://browzarr.io
Access-Control-Allow-Methods: GET, HEAD, OPTIONS
Access-Control-Expose-Headers: Content-Length, Content-Range
```

::callout{icon="i-lucide-shield-alert"}
If a store loads in Python but not in Browzarr, missing `Access-Control-Allow-Origin` on the bucket is almost always the reason. Configure the bucket (S3, GCS, or your static host) to allow the Browzarr origin.
::

## Known-good public stores

The curated catalog entries are verified to work (they already ship correct CORS settings) and double as configuration examples, e.g.:

- SeasFire Cube — `https://s3.bgc-jena.mpg.de:9000/misc/seasfire_rechunked.zarr`
- NASA MUR SST — `https://mur-sst.s3.us-west-2.amazonaws.com/zarr-v1/`
- CMIP6 stores on Google Cloud Storage
- The Icechunk tab ships its own catalog (e.g. dynamical.org forecasts and source.coop datasets)

## Tips

- Prefer stores with consolidated metadata (`.zmetadata` / `zarr.json`) — the initial parse is much faster
- Chunk sizes of 1–10 MB per chunk fetch work best
- Use the [variable sliders](/menus/variable-selection) to limit the first load of very large cubes
