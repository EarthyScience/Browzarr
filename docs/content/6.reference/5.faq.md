## Does my data leave my machine?

No. Browzarr runs entirely in your browser — chunks are fetched **directly** from the store (remote bucket or your local disk via the offline app) and processed locally. There is no backend that stores or proxies your data.

## Do I need to install anything?

Not for the [online version](https://browzarr.io). Install via npm or Julia only if you want offline use or access to local files.

## How large can my dataset be?

Browzarr fetches and renders chunks lazily, so stores much larger than your RAM work — but the slices you plot must fit in browser memory. Subset with the variable sliders and use [performance mode](/guides/performance-mode) for big cubes.

## Which Zarr versions are supported?

Zarr v2 and v3 (via zarrita.js), plus Icechunk. See [Supported formats](/reference/supported-formats).

## Can I use Browzarr for figures in a publication?

Yes — export static images or animations with the colorbar included. If Browzarr helps your research, consider citing it and starring the [repository](https://github.com/EarthyScience/Browzarr).

## How do I add my dataset to the curated catalog?

Open an issue or PR on the [repository](https://github.com/EarthyScience/Browzarr) with the store URL, a label, and a short description. Make sure the store has correct CORS settings.

## Is Browzarr open source?

Yes, under the Apache 2.0 license. See [About](/community/about).
